# Optional local Git review gate

Use this only where the project opts in. Its pre-push check reads Git's ref updates from stdin. For each branch head it accepts a local PASS receipt naming that exact commit, or an explicitly approved low-risk documentation path. An amended or rebased head needs another review, even when Git copied its notes. Tags and branch deletions are outside this check.

After independent review, capture the complete commit ID you actually inspected. With repository permission, run `python3 /path/to/review_gate.py record FULL_REVIEWED_SHA "What was checked and the result"`. The receipt lives under `refs/notes/clny-review` in this clone. A reviewer with local write access can create it. This is a workflow check. Server-enforced approvals and reviewer identity belong to the hosting platform.

For a repository opting in, invoke `python3 /path/to/review_gate.py pre-push` from its pre-push hook, preserving stdin and propagating failure. Preserve existing hooks and their inputs. For a previous intake installation, replace only its verifier after testing both routes in a disposable clone. Resolve the script from a trusted local installation outside the branch being pushed.

The default requires a receipt for every branch push. To permit low-risk documentation edits set `git config --local clny.reviewBase origin/main` and use `git config --local --add clny.trivialDocument docs/glossary.md` for each owner-approved exact path. Fetch the intended base first. The check compares the entire branch against the merge base. A non-fast-forward branch update also requires a receipt. The lightweight route admits content edits to existing regular Markdown files on that list. The rule recognizes paths and file modes; it cannot distinguish spelling corrections from changes in meaning. Keep operational, policy, and security documents off the list. Code, mixed changes, hidden directories, agent instructions and security policy require review. An unavailable configured base fails closed.
