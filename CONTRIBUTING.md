# Contributing

Keep skills portable between Codex and Claude Code. Use standard SKILL.md frontmatter with name and description, relative links, and generic capabilities rather than hardcoded tool names or personal paths. Keep the five-skill suite installable together. The suite has one version: every skill frontmatter carries the same number, and every release adds an entry with acceptance criteria to the suite changelog under clny-configure. The shared intent contract lives under clny-find-requirements; reference it rather than duplicating its rules.

Keep inference, owner decisions about a change, planning, review, and documentation curation separate. The one owner interview inside curation is the repository charter, which records standing responsibilities and never a change; it reuses the interview conduct in clny-plan-requirements rather than restating it. Test changes against realistic prompts and assess outcomes rather than exact phrases. Include intended behavior reports, ambiguous intent, adequate existing PR requirements, conditional preferences, delegated choices, documentation drift, repositories with several unlike responsibilities, brownfield repositories whose existing practices the owner does not endorse, repositories configured against an older suite version, and access limits. Do not include private company/customer examples in the distributable fixtures.

Review Markdown links and frontmatter before sharing. Run existing behavioral cases in fresh contexts with only the supplied evidence; use isolated fixtures and prohibit external writes. Record client/model, skill revision, prompt, evidence available, observed outcome, and limitations. A self-review is not an independent behavioral evaluation. Structural validation is not proof of agent performance.

Documentation must describe actual behavior and distinguish planned checks from completed checks. Keep package instructions and routing aligned when responsibilities change. Do not introduce an implementation skill or automatic PR publication implicitly.
